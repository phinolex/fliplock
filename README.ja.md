# FlipLock — マグネットなしの手帳型ケースを閉じたら画面をロック

**手帳型 / フリップ / ウォレットケースを閉じても画面が消えないのは、ケースにマグネットが入っていないからです。
FlipLock がそれを解決します。** フタを閉じる → ロック。開く → 画面が再び点灯。

マグネット不要、root 不要、ADB 不要、Shizuku 不要、サーバーなし、インターネット接続なし。

## こんな症状ではありませんか？

純正ではない手帳型ケースを買ったところ:

- フタを閉じても**画面が消えない** — カバンの中でずっと点いたまま
- フタを開けても**画面が点かない**
- Samsung の *スマートカバー* / *カバー画面* の設定が効かない、あるいは項目自体がない
- 画面が消えないせいでポケットの中で発熱し、バッテリーが減る
- 見つかるアプリは *ダブルタップで画面オフ* だけ、または root / ADB / Shizuku を要求する
- 「ポケットモード」系アプリは**暗くなるたびにロック**してしまい、かえって不便

**理由はこれです。** 純正のフリップカバーには小さな**マグネット**が仕込まれていて、端末側の
**ホールセンサー**がそれを検知します。仕組みはこれだけです。サードパーティ製ケースにはこのマグネットが
ほぼ入っていないため、Android にはケースが閉じたことを知る手段がありません。検知すべき信号そのものが
存在しないので、どんな設定をしても直りません。

**FlipLock は別の方法を採ります。** 端末前面の**照度センサー**を監視します。不透明なフタが覆いかぶさると
照度が一気に崩れます。FlipLock が探すのは固定の lux 値ではなく、その**イベント** — 速く、深く、
持続する低下 — です。この違いがすべてです。暗い部屋、横切る手、日没、屋内に入る。どれも最終的な照度は
同じくらい低くなりますが、そのどれもロックを引き起こしません。

照度は実際に **0.0 lux** まで落ち、低下率も実際に **100 %** でした。それでも FlipLock は拒否しました。
`drop too gradual`（低下が緩やかすぎる = 閉じたのではない）。直前の明るい測定値が 900 ミリ秒より前だったからです。
これはフタが降りたのではなく、部屋が暗くなっただけ。この一つの判断が、一日中スマホが勝手にロックされるのを
防いでいます。

## ロックの条件

以下を**すべて同時に**満たしたときだけロックします:

| 条件 | 目的 |
|---|---|
| `lux ≤ 閉じ判定しきい値` | 十分に暗い |
| 直前の明るい測定が 900 ミリ秒以内 | **速度** — ゆっくり暗くなる部屋を除外 |
| 基準値 ≥ 最小基準値、かつサンプル 2 件以上 | **暗い部屋** — 光だけでは判断できないので拒否 |
| 絶対低下 ≥ 5 lux | 絶対量 |
| 相対低下 ≥ 85 % | 相対量 |
| 300 ミリ秒継続 | **持続時間** — 手や影を除外 |
| ロック後 1500 ミリ秒のクールダウン | 連続発動を防止 |
| `PowerManager.isInteractive` | すでに消えている画面には触れない |

## インストール

1. 端末で APK を開いてインストールします。提供元の許可を求められたら**このアプリのみ**許可してください。
2. FlipLock を開き、**権限を有効にする**からユーザー補助サービスをオンにします。
3. **センサー診断**でフタを閉じたときに lux が動くことを確認します。
4. **ケースをキャリブレーション** → **この設定を適用**。
5. FlipLock のスイッチをオンにします。

**Samsung One UI の場合。** *制限された設定* と表示されたら、ホーム画面の**「アプリ情報」を開く**
ボタンから ⋮ メニュー → **制限された設定を許可** を選んでください。Auto Blocker 自体を無効化する必要はありません。

さらに *設定 → バッテリー → バックグラウンド使用の制限 → スリープにしないアプリ* に FlipLock を追加してください。
そうしないと One UI が数日後にサービスを終了させることがあります。

## プライバシー

APK が宣言している権限（`aapt2 dump permissions` で各自検証できます）:

```
FOREGROUND_SERVICE, FOREGROUND_SERVICE_SPECIAL_USE, POST_NOTIFICATIONS, WAKE_LOCK
```

前の 3 つは任意機能の常駐サービス専用、`WAKE_LOCK` は任意機能の「開いたら点灯」専用です。

インターネット、カメラ、マイク、連絡先、SMS、電話、位置情報、ファイル、アカウント、Bluetooth の権限は
**一つもありません**。解析ツールも Firebase もテレメトリーもサーバーもクラウドバックアップもありません。
マニフェストに `INTERNET` 権限自体が無いため、このアプリは物理的にネットワーク通信ができません。

ユーザー補助サービスは極限まで絞ってあります。`accessibilityEventTypes` を**宣言していない**ため
既定値 0 となり、ユーザー補助イベントを一切受け取りません。`canRetrieveWindowContent="false"` です。
呼び出すシステム API はただ一つ、`performGlobalAction(GLOBAL_ACTION_LOCK_SCREEN)` だけです。

## 既知の制限

- **真っ暗な部屋では動作しません。** 完全な暗闇ではフタを閉じても開けても 0 lux で、判断材料がありません。
  FlipLock は推測するくらいなら何もしない方を選びます。
- 近接センサーがフタに反応しない端末では、ハイブリッドモードも助けになりません。
  キャリブレーションがそれをはっきり教えてくれます。
- **Google Play では配布しません。** Google はユーザー補助 API をユーザー補助以外の目的に使うことを
  禁じています。Releases から APK を入手するか、Obtainium で更新を追跡してください。
